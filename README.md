# Interviewer OS Frontend

Фронтенд-платформа для проведения технических интервью с отдельными сценариями для кандидата и администратора.

Проект представляет собой функциональный MVP, а не промо-страницу. В текущей версии сервер не используется: данные хранятся локально в браузере через `localStorage`, а работа с ними вынесена в отдельный сервисный слой.

> [!IMPORTANT]
> Это демонстрационная версия. Авторизация, приглашения и хранение данных реализованы только на стороне браузера. Не используйте реальные персональные или конфиденциальные данные.

## Возможности

### Публичная часть

- единый стартовый экран;
- отдельный вход кандидата;
- отдельный вход администратора;
- вход кандидата по полной ссылке или короткому ключу;
- проверка срока действия и статуса приглашения;
- переключение русского и английского языка;
- светлая и тёмная тема без перезагрузки страницы.

### Сценарий кандидата

- вход по приглашению без отдельного ввода имени;
- выбор самооценки уровня перед началом интервью;
- запуск таймера только после подтверждения старта;
- возможность продолжить уже начатое интервью;
- одна активная задача за раз;
- рабочая область с mock-редактором кода;
- выбор языка программирования;
- отображение условий, примеров и видимых тестов;
- индикатор прогресса;
- системные сигналы и ограничения;
- завершающий экран без внутренних оценок администратора.

### Сценарий администратора

- обзорная панель;
- список участников;
- создание и редактирование участников;
- карточка участника;
- создание доступа к интервью;
- настройка предметной области;
- настройка окна доступности;
- настройка продолжительности;
- выбор языков программирования;
- вводная информация и инструкции;
- автоматическая генерация ссылки и короткого ключа;
- копирование ссылки и ключа;
- управление созданными интервью;
- просмотр результатов;
- просмотр подробного отчёта;
- экспорт отчёта в `TXT`, `Markdown`, `JSON` и `HTML`;
- настройка сценария интервью и банка заданий.

## Демонстрационный вход

### Администратор

```text
Логин: admin
Пароль: admin
```

### Кандидат

Кандидат входит по ссылке или короткому ключу, созданному администратором.

Чтобы проверить полный сценарий:

1. Откройте `/admin/login`.
2. Войдите под учётной записью `admin / admin`.
3. Создайте участника или сразу создайте новое интервью.
4. Скопируйте полученную ссылку либо короткий ключ.
5. Перейдите по ссылке в том же браузере и на том же домене.
6. Запустите интервью от имени кандидата.

> Данные `localStorage` не синхронизируются между разными браузерами, устройствами, доменами и режимом инкогнито.

## Запуск проекта

### Требования

Для запуска потребуется актуальная LTS-версия Node.js и npm.

### Установка

```bash
git clone https://github.com/sar2718/interviewer-os-frontend.git
cd interviewer-os-frontend
npm ci
```

### Режим разработки

```bash
npm run dev
```

После запуска Vite выведет локальный адрес приложения в терминале.

Обычно это:

```text
http://localhost:5173
```

### Production-сборка

```bash
npm run build
```

Готовые файлы будут размещены в директории `dist`.

### Локальная проверка production-сборки

```bash
npm run preview
```

## Основные маршруты

### Публичные маршруты

| Маршрут | Назначение |
|---|---|
| `/` | Стартовый экран |
| `/candidate-access` | Вход кандидата по ссылке или ключу |
| `/admin/login` | Вход администратора |
| `/invite/:hash` | Проверка и активация приглашения |

### Маршруты кандидата

| Маршрут | Назначение |
|---|---|
| `/candidate` | Подготовка к интервью и выбор уровня |
| `/candidate/session/:sectionId` | Рабочее пространство интервью |
| `/candidate/session/:sectionId/complete` | Завершающий экран |

### Маршруты администратора

| Маршрут | Назначение |
|---|---|
| `/admin` | Обзорная панель |
| `/admin/candidates` | Список участников |
| `/admin/candidates/new` | Создание участника |
| `/admin/candidates/:candidateId` | Карточка участника |
| `/admin/sections` | Список интервью |
| `/admin/sections/new` | Создание интервью и приглашения |
| `/admin/results` | Результаты |
| `/admin/reports/:sectionId` | Подробный отчёт |
| `/admin/settings` | Настройки интервью |

## Архитектура

Интерфейс разделён на три основные зоны:

```text
Публичная часть
      │
      ├── Вход администратора
      │          │
      │          └── Панель администратора
      │
      └── Вход по приглашению
                 │
                 └── Рабочее пространство кандидата
```

Бизнес-логика вынесена из страниц в сервисы:

- `src/services/storage.service.ts` — базовый слой хранения;
- `src/services/auth.service.ts` — авторизация и проверка приглашений;
- `src/services/admin.service.ts` — административные сценарии;
- `src/services/candidate.service.ts` — кандидатский сценарий;
- `src/services/interviewState.service.ts` — синхронизация состояния интервью.

Доменные типы и контракты находятся в `src/types`.

## Как работает mock backend

Серверная часть в текущей версии отсутствует.

Данные сохраняются в `localStorage` браузера. Основные коллекции:

- `candidates`;
- `sections`;
- `results`;
- `reports`;
- `settings`;
- `tasks`;
- `authSession`.

Начальное состояние создаётся из файлов директории `src/mock`.

По умолчанию:

- список участников пуст;
- список интервью пуст;
- результаты и отчёты отсутствуют;
- банк заданий и настройки создаются автоматически;
- доступ администратора выполняется через `admin / admin`.

Очистка данных сайта в браузере удалит созданных участников, интервью и результаты.

## Подключение реального backend API

Архитектура проекта позволяет сохранить страницы, компоненты и TypeScript-типы, заменив реализацию сервисного слоя.

Основные файлы для интеграции:

```text
src/services/auth.service.ts
src/services/admin.service.ts
src/services/candidate.service.ts
src/services/storage.service.ts
```

Для production-версии потребуется:

1. Заменить чтение и запись в `localStorage` на HTTP-запросы.
2. Перенести авторизацию на сервер.
3. Использовать безопасные сессии или access/refresh tokens.
4. Генерировать приглашения на сервере.
5. Проверять срок действия приглашения на серверной стороне.
6. Хранить результаты и отчёты в базе данных.
7. Добавить серверную валидацию входных данных.
8. Настроить разграничение прав кандидата и администратора.
9. Исключить хранение секретов и паролей во frontend-коде.

Типы из `src/types` можно использовать как основу для DTO и API-контрактов.

## Ограничения текущей версии

- отсутствует реальный backend;
- данные доступны только в текущем браузере;
- авторизация является демонстрационной;
- приглашения не предназначены для защиты реальных интервью;
- mock-редактор не выполняет отправленный код;
- нет синхронизации между устройствами;
- нет совместной работы в реальном времени;
- нет серверной проверки ответов;
- нет восстановления данных после очистки `localStorage`.
